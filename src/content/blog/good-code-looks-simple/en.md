Good code looks simple.
Bad code looks clever.

But writing clever code… that looks simple is probably one of the hardest things in software development.

Because behind that simplicity, there is often:

- [a clean split into modules](/blog/coupling-is-the-worst-thing-in-a-codebase/)
- the right abstractions
- only the abstractions you need
- explicit variable names
- real overall consistency
- invisible but solid choices

"Impressive" code is often easy to write.
Obvious, readable code that lasts takes far more mastery.

Simple-looking code is [what I aim for, day after day](/work-with-me/).
